# План разработки — «График смен» (shifts-app)

## 1. Инфраструктура и окружение

- [ ] Проверить версии Node.js, pnpm, установленные в проекте.
- [ ] Убедиться, что все зависимости установлены (pnpm install).
- [ ] Настроить переменные окружения (`.env.local`):
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - (опционально) `ALLOWED_DEV_ORIGINS` для разработки.
- [ ] Проверить работу dev-сервера (`pnpm dev`), убедиться, что страница открывается.
- [ ] Настроить ESLint и Prettier (если не настроены) – проверить конфиги.
- [ ] Настроить TypeScript (уже есть), проверить `tsconfig.json` и отсутствие ошибок типов.
- [ ] Настроить пути импортов (alias `@/` уже есть).

---

## 2. Модели данных и типы (пакет `@shifts/types`)

- [ ] **Проверить и дополнить** Zod-схемы в `packages/types/src/index.ts`:
  - [ ] `ShiftType` – добавить поля `createdAt`/`updatedAt` (опционально).
  - [ ] `Shift` – добавить поле `userId` (если поддержка нескольких пользователей).
  - [ ] `Preset` – убедиться, что `sequence` — массив `ShiftType.id`.
  - [ ] `PresetMeta` – добавить поле `userId` и индексы для оптимизации.
  - [ ] Создать схемы для валидации форм (например, для создания/редактирования типов смен, пресетов).
- [ ] Экспортировать все схемы и типы из основного файла.
- [ ] Написать unit-тесты для схем (опционально, но желательно).

---

## 3. Работа с данными (Supabase + React Query)

- [ ] **Создать клиент Supabase** (`shared/lib/supabase.ts`) с настройками из env.
- [ ] **Определить типы таблиц** в Supabase (можно использовать автоматическую генерацию типов через `supabase gen types`).
- [ ] **Создать API-сервисы** для взаимодействия с таблицами:
  - [ ] `shiftTypesApi` – CRUD для типов смен.
  - [ ] `shiftsApi` – CRUD для смен (по дате, по диапазону, по пользователю).
  - [ ] `presetsApi` – CRUD для пресетов.
  - [ ] `presetMetaApi` – работа с метаданными пресетов.
- [ ] **Настроить React Query**:
  - [ ] Создать `QueryClient` с настройками (по умолчанию, staleTime, retry).
  - [ ] Обернуть приложение в `QueryClientProvider`.
  - [ ] Написать хуки для каждого API (useQuery, useMutation) с инвалидацией кэша.
- [ ] **Добавить поддержку офлайн/локального хранилища** (persistQueryClient) для работы без интернета (если нужно).

## 4. Управление состоянием (Zustand)

- [ ] **Создать хранилище для текущего состояния приложения**:
  - [ ] `useAppStore` – хранит выбранную дату, отображаемый месяц/год, текущий пользователь (если есть).
  - [ ] `useShiftStore` – кэширует загруженные смены для быстрого доступа (можно совместить с React Query).
  - [ ] `usePresetStore` – хранит список пресетов и текущий выбранный пресет.
- [ ] Интегрировать Zustand с React Query (синхронизация при мутациях).

  - [ ] Отображать сетку календаря (7 колонок).
  - [ ] Каждая ячейка – день, клик открывает диалог редактирования смены.

  - [ ] Индикация выходных/праздников (опционально).

  - [ ] Редактирование и удаление.
- [ ] **Страница управления пресетами (`/settings/presets`)**:
  - [ ] Список пресетов с возможностью редактирования.
  - [ ] Форма создания пресета: название и последовательность типов смен (Drag-and-drop или мультиселект).
  - [ ] Возможность применить пресет к выбранному диапазону дат (с выбором режима: overwrite, fill-empty, continue).

## 7. Бизнес-логика (применение пресетов)

- [ ] **Реализовать функцию применения пресета** на выбранный интервал дат:
  - [ ] Получить `preset.sequence` (массив id типов смен).
  - [ ] Учесть `PresetMeta.referenceDate` и `referenceIndex` для продолжения с правильной позиции.
  - [ ] Поддержать три режима:
    - `overwrite` – заменять все существующие смены.
    - `fill-empty` – заполнять только пустые дни.
    - `continue` – продолжить последовательность, начиная с последней применённой позиции.
  - [ ] Сохранить обновлённый `PresetMeta` после применения.
- [ ] **Обработка конфликтов** – что делать, если на дату уже есть смена (спросить пользователя).
- [ ] **Добавить прогресс-индикатор** при массовом применении.
